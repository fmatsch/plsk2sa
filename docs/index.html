plsk2sa

Zieht Domains mit Web, Mail und Datenbanken von einem Plesk-Server auf einen eigenen Ubuntu-Server – ohne Panel. Ein Assistent führt durch Verbinden, Prüfen, Auswahl und Umzug; DNS-Änderungen werden gleich mitgeliefert.

⬇ Herunterladen Quellcode auf GitHub
Windows · macOS (Apple Silicon) · Linux · kostenlos, MIT-Lizenz

So läuft der Umzug

  1. Plesk-Server verbindenPer SSH, mit Passwort, Schlüsseldatei oder SSH-Agent.
  2. PrüfenRoot-Zugriff, Plesk, rsync, Mail-Passwörter, Speicherplatz – Fehler stoppen, Warnungen werden erklärt.
  3. AuswählenDomains und Subscriptions, mit Größe und PHP-Version.
  4. Zielserver verbindenEin frischer Ubuntu 22.04/24.04. Eigene Prüfungen für Ports, Port 25 und Reverse-DNS.
  5. UmziehenErst die Vorschau, dann der echte Lauf mit Live-Log.

Funktionen

Vorschau vor dem Ernstfall

Die Vorschau listet jeden Befehl, der laufen würde, und ändert nichts – weder am Ziel noch am Plesk-Server.

Änderungen am Plesk-Server immer sichtbar

Vorher, während des Laufs und danach: Das Programm zeigt jede Änderung am Quellserver an und ob sie wieder entfernt wurde.

Direkt von Server zu Server

Dateien und Postfächer laufen per rsync vom Plesk-Server direkt zum Ziel, nicht über deinen Rechner. Der dafür nötige SSH-Schlüssel ist temporär und wird am Ende entfernt.

DNS-Plan

Liegt das DNS woanders, zeigt es genau, welche Einträge sich ändern. Hostet Plesk das DNS, gibt es fertige Zonendateien zum Importieren.

Mail-Passwörter bleiben

Postfächer ziehen mit ihren Passwörtern um (Dovecot), inklusive Aliasen, Maildirs und neuem DKIM-Schlüssel.

Web und Datenbanken

nginx und PHP-FPM mit eigenem Pool pro Domain, MariaDB mit Dump und Restore, Zertifikate danach per certbot.

Demo-Modus

Der ganze Assistent lässt sich mit simulierten Servern durchklicken – ohne dass irgendetwas verbunden oder geändert wird.

Auch per Kommandozeile

Dieselbe Engine läuft ohne Oberfläche, mit Trockenlauf, Checks und DNS-Plan.

Gut zu wissen

Bitte zuerst die Vorschau laufen lassen. Das Programm ist durch Tests mit simulierten Servern abgesichert, aber noch nicht an einer echten Plesk-Installation erprobt. Verbinden, Prüfungen und Vorschau ändern nichts.

  • Ein Programm, angezeigt im Browser: Die Datei ist eigenständig – ohne Python, ohne Installation, ohne Internetzugang. Beim Start öffnet sie ihre Oberfläche im Standardbrowser (ein kleiner Webserver, der nur auf deinem eigenen Rechner erreichbar ist). Ein eigenes Fenster gibt es nicht.
  • Was auf dem Plesk-Server passiert: Ein echter Lauf trägt vorübergehend einen markierten SSH-Schlüssel in ~/.ssh/authorized_keys ein und entfernt ihn am Ende wieder – auch nach Fehlern oder Abbruch. Sonst wird dort nichts verändert oder gelöscht.
  • Nicht automatisch migriert: Subdomains, Domain-Aliase, Cronjobs und FTP-Konten. Die Prüfungen listen, was sie finden. DNS wird geplant, aber nie bei einem DNS-Anbieter verändert.
  • Passwörter: SSH-Passwörter werden nur zum Verbinden benutzt und weder gespeichert noch protokolliert. Der Arbeitsordner enthält Datenbank-Dumps und die Mail-Passwörter der gewählten Domains.
  • SmartScreen / Gatekeeper: Die Programme sind nicht code-signiert. Windows zeigt „Weitere Informationen → Trotzdem ausführen“, macOS fragt beim ersten Start (Rechtsklick → Öffnen). Sie werden bei jedem Release öffentlich auf GitHub aus dem Quellcode gebaut; Prüfsummen liegen bei.
